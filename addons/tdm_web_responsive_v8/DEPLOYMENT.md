# 部署与回滚手册

## 上线前提

1. 明确 Odoo 配置文件、服务名、数据库名、filestore 和自定义 addons 路径。
2. 完成数据库、filestore、配置文件、自定义 addons 和服务定义备份。
3. 测试环境与生产环境隔离；先在生产数据库副本完成安装与手机回归。
4. 不覆盖 Odoo 核心目录，不把模块直接放入官方 addons 目录。

## 测试环境安装

1. 把整个 `tdm_web_responsive_v8` 目录放入独立的自定义 addons 路径。
2. 确认该路径已写入 `addons_path`。
3. 使用测试数据库执行模块清单更新：

   ```bash
   ./openerp-server -c /path/to/test.conf -d TEST_DB \
     -u tdm_web_responsive_v8 --stop-after-init
   ```

4. 重启测试服务，清理浏览器缓存后登录。
5. 在 360px、390px、768px 和桌面宽度下完成验收。

## 必测业务路径

- 顶部应用菜单、左侧二级菜单的打开、跳转和关闭。
- 客户、供应商、产品、销售单、采购单、库存单的列表与表单。
- 新建、编辑、保存、取消、删除、搜索、筛选和分组。
- one2many/many2many 明细表、弹窗、页签、状态栏和附件上传。
- 现有自定义模块的关键单据，以及中文长字段名和多公司切换。
- PC 浏览器回归，确认原桌面布局与业务操作无退化。

## 生产发布

在测试验收通过后安排维护窗口：

1. 再做一次增量前备份并记录校验值。
2. 把已验收的同一版本模块复制到生产自定义 addons 路径。
3. 对指定生产数据库执行 `-u tdm_web_responsive_v8 --stop-after-init`。
4. 重启 Odoo 服务，检查启动日志中不存在 XML、QWeb、JS 或资产加载错误。
5. 用 PC 和手机执行登录、菜单、列表、表单、保存四项冒烟验证。

## 回滚

若出现阻断性问题：

1. 停止 Odoo 服务。
2. 从 `ir_module_module` 正常卸载模块，或先恢复上线前数据库备份。
3. 移出 `tdm_web_responsive_v8` 目录。
4. 恢复上线前配置与静态资产缓存并重启服务。
5. 验证 PC 端核心业务路径，再分析测试环境中的冲突。

生产操作必须使用实际环境的服务名、配置路径和数据库名；不要照抄文档中的占位符。
